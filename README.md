# FAIZA GOLD

Система кассового учёта ООО «Фаиза». React 19 и Vite 7 обращаются к ASP.NET Core API. Слой Domain описывает кассы и документы, Application содержит контракты и финансовые правила, Infrastructure сохраняет операции через EF Core и Npgsql. Migrator обновляет схему PostgreSQL.

## Локальный запуск на Windows

Установите .NET SDK 10.0.203, Node.js 22 и PostgreSQL 18 с клиентскими утилитами. Локальные скрипты ожидают PostgreSQL в стандартном каталоге Program Files и сервер на порту 5432. Команды выполняются из корня репозитория.

1. Выполните `dotnet build backend/FaizaCash.sln` и `npm --prefix frontend ci`.
2. При первой установке запустите `node scripts/configure-local.mjs` и передайте пароль локального администратора PostgreSQL через стандартный ввод. Скрипт создаёт отдельную роль, базу разработки и базу с суффиксом _test. Сохраните сгенерированный файл .runtime/local.json на машине демонстрации. Повторный запуск создаёт новые базы и заменяет этот файл.
3. Запустите `node scripts/run-local.mjs`. API разработки применяет миграции при запуске. Проверьте http://localhost:5080/health.
4. Во втором терминале выполните `npm --prefix frontend run dev` и откройте адрес, выведенный Vite. Начальные данные для входа администратора находятся в .runtime/local.json. При первом входе задайте новый пароль.

Для наполнения пустой локальной базы синтетическим набором выполните `node scripts/seed-demo.mjs`. После первой смены пароля задайте его через переменную `FAIZA_ADMIN_PASSWORD`. Скрипт откажется добавлять данные, если в базе уже есть кассы. Он создаёт:

- три кассы в филиалах Душанбе, Худжанд и Бохтар с начальными остатками;
- смены за 20 дней, одна из них закрыта с недостачей 15 сомони, чтобы заполнить блок «Требует внимания»;
- межкассовый перевод;
- три задолженности: с частичной оплатой, просроченную и с ответственным представителем;
- квитанции торгового представителя;
- 3 черновика и открытые смены на сегодня.

Используйте этот сценарий только в учебной базе.

### Начальный остаток кассы и смены

Администратор задаёт начальный остаток кассы один раз: «Кассы» → «Задать начальный остаток» или `POST /api/cashboxes/{id}/opening`. Это возможно только до первой смены и первого проведённого документа. При открытии смены форма подставляет расчётный остаток. Сервер отклоняет другое значение с кодом 409 и сообщает расчётную сумму. Фактическое расхождение наличности фиксируется при закрытии смены.

### Резервное копирование и проверка восстановления

«Резервные копии» → «Создать копию» → «Проверить» → «Тест восстановления». Тест восстановления разворачивает копию только в отдельную одноразовую базу из `ConnectionStrings:BackupRestore` (`Backups:RestoreHost`, `Backups:RestoreDatabase`). Затем он сверяет остатки касс, суммы задолженностей и платежей, число проведённых документов и внешние ключи с данными на момент копирования и очищает базу. Рабочая база не перезаписывается. В production Compose такая база — отдельный контейнер `backup-restore-db` на `tmpfs`.

## Запуск с нуля через Docker Compose

1. Установите Docker Desktop и дождитесь запуска Docker Engine.
2. Скопируйте `.env.example` в `.env`. Задайте собственные длинные случайные значения для `POSTGRES_PASSWORD`, `JWT__KEY` (не менее 32 символов) и `SEED__ADMINPASSWORD`. Файл `.env` не добавляйте в Git.
3. В корне репозитория выполните `docker compose up --build -d` и дождитесь состояния healthy у сервиса `db`. Для остановки: `docker compose down`. Чтобы сохранить учебную базу, не добавляйте `-v`.
4. Откройте http://localhost:8085 и войдите как `admin` с локальным начальным паролем из `.env`. При первом входе система предложит сменить пароль.
5. Для синтетических кассовых данных после смены пароля задайте `FAIZA_API=http://localhost:5085`, `FAIZA_ADMIN_LOGIN=admin` и `FAIZA_ADMIN_PASSWORD` в текущем терминале, затем запустите `node scripts/seed-demo.mjs`. Скрипт добавляет данные только при пустом наборе касс и не очищает существующие записи.
6. Для отдельных пользователей демонстрации запустите `node scripts/seed-demo-users.mjs` с теми же переменными. Скрипт создаст роли `accountant`, `cashier`, `manager`, `auditor` и назначит им доступ к первой кассе. Случайные локальные пароли находятся только в игнорируемом Git файле `.runtime/demo-users.json`; у каждого пользователя включена смена пароля при первом входе. Администраторская учётная запись задаётся через `.env`.

Команды `docker compose config --quiet` проверяют только конфигурацию и не запускают контейнеры. Интеграционные тесты отдельно настроены на `_test` БД; не запускайте их на демонстрационной базе.

## Проверки

Команда `node tests/run-all.mjs` по очереди запускает:

1. сборку;
2. xUnit;
3. frontend-тесты и сборку frontend;
4. API-наборы на PostgreSQL: `integration`, `security`, `catalog`, `ledger-integrity`, `tests/integration/p0.mjs`, `invariants.mjs`, `restore.mjs`, `p1.mjs`, `demo-seed.mjs`;
5. браузерный E2E `tests/e2e.mjs` на Playwright.

Если какой-то набор упал, остальные всё равно выполняются, а итог печатается в конце. Фактические результаты — в `docs/TESTING.md`.

Наборы PostgreSQL пересоздают схему базы `_test` (имя проверяется). `restore.mjs` дополнительно поднимает одноразовый контейнер `postgres:18.3-alpine` на `127.0.0.1:55432` и требует Docker. Используйте исключительно одноразовую тестовую базу. Пароли, cookie, дампы и локальные настройки содержат конфиденциальные данные.

## Защита диплома · 8 минут

| Время | Действие |
|---|---|
| 0–1 мин | Объяснить путь документа от React через API до PostgreSQL. |
| 1–2 мин | Показать доступ администратора и кассира, выбрать филиал и кассу. Для демонстрации доступны роли admin, accountant, cashier, manager и auditor. Локальные учётные данные для четырёх неадминистративных ролей находятся в `.runtime/demo-users.json`. |
| 2–4 мин | Открыть смену в пустой кассе (расчётный остаток 0,00 подставляется). Провести приход 1 000 и расход 250 сомони. Сверить остаток 750 на dashboard. Показать перевод между кассами: остатки обеих касс изменились согласованно. |
| 4–6 мин | Показать частичную оплату задолженности, остаток долга и ответственного представителя. Открыть кассовую книгу и «Выгрузку отчётов» (смены, филиал, переводы, задолженности, представители — CSV/PDF). |
| 6–8 мин | Закрыть смену, показать блок «Требует внимания», журнал аудита, тест восстановления копии и результаты `node tests/run-all.mjs`. |

Для показа используйте только синтетические данные. Браузерный маршрут, два восстановления подряд в изолированную базу и демо-наполнение проверяются автоматически (`tests/e2e.mjs`, `tests/integration/restore.mjs`, `tests/integration/demo-seed.mjs`). Production Compose с TLS на реальном домене этими тестами не проверяется.

Вне объёма дипломной версии (ТЗ V1.1 §2, V2.0 §16): склад, товары, заказы и продажи как самостоятельные процессы, банковские интеграции, электронная подпись.
