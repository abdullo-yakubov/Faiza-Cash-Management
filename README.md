# FAIZA GOLD

Система регистрации и учёта кассовых операций бухгалтерии ООО «Фаиза». Дипломный проект на тему «Автоматизация регистрации и учёта кассовых операций в бухгалтерии ООО „Фаиза“».

Система ведёт единый журнал наличных: приходные и расходные документы, смены, межкассовые переводы, задолженности контрагентов, квитанции торговых представителей, авансы подотчётным лицам и инвентаризации кассы. Расходы выше порога проходят согласование руководителя. Проведённые документы и журнал аудита защищены от изменения на уровне PostgreSQL, а администратор не выполняет финансовых операций (разделение обязанностей).

**Стек:** ASP.NET Core 10 Minimal API · EF Core 10 + Npgsql · PostgreSQL 18 · QuestPDF · React 19 + Vite 7 (JavaScript) · Docker Compose · Caddy · GitHub Actions.

## Возможности

| Область | Что умеет |
|---|---|
| Кассовые документы | Черновики ПКО/РКО, проведение с автонумерацией, сторно, печатные формы PDF с суммой прописью, вложения (сканы, фото) |
| Контроль | Остаток не уходит в минус ни на одну дату, лимит кассы, проведение только в открытую смену, согласование расходов выше порога |
| Смены и наличность | Открытие и закрытие смены, недостача и излишек, пересчёт по купюрам, акты инвентаризации |
| Расчёты | Задолженности и распределение платежей, квитанции представителей, авансы и авансовые отчёты |
| Отчётность | Кассовая книга, отчёты по филиалам, сменам, переводам, задолженностям, представителям, авансам — экран, CSV, PDF; панель показателей |
| Безопасность | Пять ролей и доступ по кассам, JWT + refresh-cookie с ротацией, ограничение частоты, неизменяемый аудит |
| Надёжность | Шифрованные резервные копии (AES-256-GCM), проверка и тестовое восстановление в изолированную базу, панель состояния для администратора |

Функции согласования, вложений, авансов, инвентаризации, мультивалютности, панели администратора, логотипа и аватаров относятся к волне 1 и описаны в ТЗ как требования.

## Быстрый старт (Docker Compose)

1. Установите Docker Desktop и дождитесь запуска Docker Engine.
2. Скопируйте `.env.example` в `.env` и задайте длинные случайные значения `POSTGRES_PASSWORD`, `JWT__KEY` (не менее 32 символов) и `SEED__ADMINPASSWORD`. Файл `.env` не добавляйте в Git.
3. Выполните `docker compose up --build -d` и дождитесь состояния healthy у сервиса `db`. Остановка: `docker compose down` (без `-v`, чтобы сохранить учебную базу).
4. Откройте http://localhost:8085 и войдите как `admin` с паролем из `.env`. При первом входе система попросит сменить пароль. API доступен на http://localhost:5085.
5. Демо-данные (только для учебной базы): задайте `FAIZA_API=http://localhost:5085`, `FAIZA_ADMIN_LOGIN=admin`, `FAIZA_ADMIN_PASSWORD=<новый пароль>` и выполните `node scripts/seed-demo.mjs`, затем `node scripts/seed-demo-users.mjs` — будут созданы пользователи ролей `accountant`, `cashier`, `manager`, `auditor`. Их пароли сохраняются только в игнорируемом Git файле `.runtime/demo-users.json`.

`seed-demo.mjs` добавляет данные только при пустом наборе касс: три кассы (Душанбе, Худжанд, Бохтар) с начальными остатками, смены за 20 дней (одна — с недостачей 15 сомони), перевод, три задолженности, квитанции представителя, черновики и открытые смены на сегодня.

## Локальный запуск на Windows

Нужны .NET SDK 10.0.203, Node.js 22 и PostgreSQL 18 с клиентскими утилитами (стандартный каталог Program Files, порт 5432). Команды выполняются из корня репозитория.

1. `dotnet build backend/FaizaCash.sln` и `npm --prefix frontend ci`.
2. Один раз: `node scripts/configure-local.mjs` (пароль администратора PostgreSQL — через стандартный ввод). Скрипт создаёт отдельную роль, базу разработки и базу с суффиксом `_test`, а также файл `.runtime/local.json`. Повторный запуск пересоздаёт базы.
3. `node scripts/run-local.mjs` — API на http://localhost:5080 (миграции применяются при запуске; проверка: `/health`).
4. Во втором терминале: `npm --prefix frontend run dev` и откройте адрес, выведенный Vite. Начальные данные администратора — в `.runtime/local.json`.

Начальный остаток кассы задаётся администратором один раз («Кассы» → «Задать начальный остаток») до первой смены и первого проведённого документа. При открытии смены подставляется расчётный остаток; другое значение сервер отклоняет с кодом 409.

Production-развёртывание (TLS, отдельные роли БД, контейнер для тестового восстановления) описано в [руководстве администратора](docs/Руководство_администратора.md).

## Проверки

`node tests/run-all.mjs` по очереди выполняет сборку, xUnit, тесты и сборку frontend, API-наборы на PostgreSQL (`integration`, `security`, `catalog`, `ledger-integrity`, `p0`, `invariants`, `restore`, `p1`, `demo-seed`, `p2`) и браузерный E2E на Playwright. При успехе печатается `All suites passed.`

Наборы PostgreSQL пересоздают схему базы `_test` (имя проверяется) — никогда не запускайте их на демонстрационной базе. `restore.mjs` требует Docker. Подробности, добавление тестов и трассировка требований — в [docs/TESTING.md](docs/TESTING.md).

Качество кода: правила в `.editorconfig`, ESLint (`eslint.config.mjs`) и Prettier (`.prettierrc.json`). В CI `dotnet format --verify-no-changes` и ESLint пока работают в режиме предупреждения.
