# FAIZA GOLD

Система кассового учёта ООО «Фаиза». React 19 и Vite 7 обращаются к ASP.NET Core API. Слой Domain описывает кассы и документы, Application содержит контракты и финансовые правила, Infrastructure сохраняет операции через EF Core и Npgsql. Migrator обновляет схему PostgreSQL.

## Локальный запуск на Windows

Установите .NET SDK 10.0.203, Node.js 22 и PostgreSQL 18 с клиентскими утилитами. Локальные скрипты ожидают PostgreSQL в стандартном каталоге Program Files и сервер на порту 5432. Команды выполняются из корня репозитория.

1. Выполните `dotnet build backend/FaizaCash.sln` и `npm --prefix frontend ci`.
2. При первой установке запустите `node scripts/configure-local.mjs` и передайте пароль локального администратора PostgreSQL через стандартный ввод. Скрипт создаёт отдельную роль, базу разработки и базу с суффиксом _test. Сохраните сгенерированный файл .runtime/local.json на машине демонстрации. Повторный запуск создаёт новые базы и заменяет этот файл.
3. Запустите `node scripts/run-local.mjs`. API разработки применяет миграции при запуске. Проверьте http://localhost:5080/health.
4. Во втором терминале выполните `npm --prefix frontend run dev` и откройте адрес, выведенный Vite. Начальные данные для входа администратора находятся в .runtime/local.json. При первом входе задайте новый пароль.

Для наполнения пустой локальной базы синтетическим набором выполните `node scripts/seed-demo.mjs`. После первой смены пароля задайте его через переменную `FAIZA_ADMIN_PASSWORD`. Скрипт откажется добавлять данные, если в базе уже есть кассы; он создаёт 21 проведённый документ, 3 черновика, закрывает исторические смены и оставляет сегодняшнюю смену открытой. Используйте этот сценарий только в учебной базе.

Для контейнерной среды подготовьте локальный .env по .env.example и выполните `docker compose up --build`. Интерфейс доступен на http://localhost:8085. Для проверки одного только описания сервисов выполните `docker compose config --quiet`.

## Проверки

Команда `node tests/run-all.mjs` собирает приложение, запускает xUnit, frontend и API-проверки. Наборы PostgreSQL пересоздают схему базы _test. Используйте исключительно одноразовую тестовую базу. Пароли, cookie, дампы и локальные настройки содержат конфиденциальные данные.

## Защита диплома · 8 минут

| Время | Действие |
|---|---|
| 0–1 мин | Объяснить путь документа от React через API до PostgreSQL. |
| 1–2 мин | Показать доступ администратора и кассира, выбрать филиал и кассу. Для демонстрации доступны роли admin, accountant, cashier, manager и auditor. Назначить тестовым сотрудникам доступ к учебным кассам. |
| 2–4 мин | Открыть смену с нулевым остатком в пустой кассе. Провести приход 1 000 и расход 250 сомони. Сверить остаток 750 на dashboard. |
| 4–6 мин | Показать частичную оплату задолженности и остаток долга. Открыть кассовую книгу за выбранный день и экспортировать отчёт. |
| 6–8 мин | Закрыть смену, показать журнал действий и результаты тестов. |

Для показа используйте только синтетические данные. Успешное исполнение контейнерного сценария, полный браузерный маршрут и восстановление копии следует подтвердить на демонстрационной машине.
