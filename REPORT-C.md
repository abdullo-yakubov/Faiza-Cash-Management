## 2. Что не сделано и почему

- **Сверка структуры ТЗ с текстом ГОСТ 34.602-2020**: текста стандарта в репозитории нет. Структура составлена по памяти о стандарте (разделы 1–10, включая «Порядок разработки АС», появившийся в редакции 2020 г.; подразделы 4.1 и 4.3, включая метрологическое обеспечение) и по перечню из задания. **Нужно сверить с официальным текстом и методическими указаниями кафедры.**
- **Нормативная база РТ** не указана — только места `[УТОЧНИТЬ: …]` (раздел 10 ТЗ). Ничего не выдумано.
- **Номиналы сомони/дирамов** в документации не перечислены, оставлено `[УТОЧНИТЬ: данные НБТ]` — сидирование и сверку с НБТ по заданию выполняет агент A.
- **Скриншоты** — только заглушки-ссылки (`docs/screenshots/*.png`); снять их можно после слияния B.
- **Prettier в CI не запускается** — включение до общего переформатирования сломает CI и слияние.
- **Фактические результаты прогона** в TESTING.md не заполнены (таблица-шаблон): тесты по условиям задачи запускает только A.

## 3. Принятые решения

1. **Функции волны 1 в ТЗ — требования** (целевое состояние), в диаграммах помечены «W1». Имена новых сущностей на ER-диаграмме (`Advance`, `AdvanceReportLine`, `Attachment`, `CashInventory`, `CashInventoryLine`, `ShiftDenomination`, `Denomination`, `ExchangeRate`) — рабочие; после слияния A сверить с фактической моделью.
2. **Матрица прав**: у admin убраны только действия из утверждённого перечня финансовых операций. Создание задолженностей, создание/передача/отмена квитанций и начальный остаток оставлены за admin — вынесено как вопрос заказчику (прил. А, примечание 1; ADR-0007). Номиналы — только admin (по контракту «админ может редактировать»).
3. **Согласование**: граница порога включается («сумма ≥ порога»), как в контракте.
4. **LF вместо CRLF.** Все 171 текстовых файла в индексе уже в LF; CI и контейнеры работают на Linux; `dotnet format` в CI на Linux с правилом CRLF «упал» бы на каждом файле. Для Windows-разработчика: `core.autocrlf=true` на этой машине выдаёт CRLF в рабочую копию, и редакторы смешивают окончания. Поэтому `.editorconfig` → `end_of_line = lf`, а `.gitattributes` → `* text=auto eol=lf` (кроме `*.cmd/*.bat/*.ps1` — CRLF). Содержимое в индексе не меняется, конфликтов слияния это не создаёт. Если после слияния в чьей-то рабочей копии `git status` покажет «фантомные» изменения, выполните `git add --renormalize .` — дифф будет пустым.
5. **Миграции EF** исключены из форматирования (`generated_code = true`, `charset = unset`): инструмент создаёт их с BOM, а миграции не редактируются задним числом.
6. **Уровни анализаторов** в `.editorconfig`: реальные риски (`CA1305` культура при форматировании денег/дат, `CA2100` SQL из строк, `CA2016` CancellationToken, `IDE0161` file-scoped namespace) — warning; стилистика — suggestion, чтобы не засорять сборку.
7. **ESLint-конфиг в корне** (`eslint.config.mjs`, а не `.js` — в корне нет `package.json` с `"type": "module"`). Правило `no-restricted-globals: parseFloat` закрепляет инвариант 4 CLAUDE.md (никакого float для денег).
8. **ADR-0005** честно отмечен как «частично реализован»: обработчики сгруппированы по файлам, но основной файл ~80 КБ — рекомендация разнести по срезам.
9. Новый `docs/CLAUDE.md` указывает на ТЗ по ГОСТ как на источник требований и на прил. А как на матрицу прав.
