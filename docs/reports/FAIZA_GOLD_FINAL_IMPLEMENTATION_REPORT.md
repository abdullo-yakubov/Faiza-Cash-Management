# FAIZA GOLD / Faiza Cash — Итоговый отчёт

## Краткое заключение

Основные функции кассового учёта, межкассовых переводов, задолженностей, PDF-отчётов, панели показателей и ролевой изоляции реализованы и проверены. Проект готов к демонстрации и защите диплома с оговоркой по резервному восстановлению. Готовность к production не подтверждена: восстановление резервной копии в изолированную БД не настроено и намеренно отключено.

## Изменения этого продолжения

- Dashboard рассчитывает агрегаты на сервере, показывает показатели за день/7 дней/месяц и баланс во времени; денежные значения форматируются без преобразования в двоичную арифметику для отображения.
- Данные задолженностей и уведомления о просрочке скрыты для кассиров.
- Администратор может задать сотруднику временный пароль; операция отзывает refresh-токены, требует сменить пароль при следующем входе и не записывает пароль в аудит.
- Открытие смены использует дату Душанбе, устраняя расхождение с UTC около полуночи.
- UI резервных копий больше не показывает недоступное восстановление как рабочее действие; API явно сообщает о блокировке.

Рабочая копия содержит и другие ранее существовавшие незакоммиченные изменения; они не очищались и не включались в этот перечень.

## Оставшиеся ограничения

1. Настроить отдельную тестовую БД и ограниченные права подключения для восстановления; после настройки провести полный restore-дрилл и сверить восстановленные данные.
2. Повторить проверку backup/restore на целевом deployment-окружении и подтвердить защищённость хранилища резервных копий на уровне ОС/контейнера.
3. До выполнения пункта 1 не считать backup/restore готовым для production.
