# План P0/P1/P2

## P0 — только после согласования требований

1. Зафиксировать policy смен: open/close, opening balance, variance, reopen, запрет операций после close.
2. Зафиксировать policy лимита: hard block или warning, момент проверки и исключения.
3. Реализовать API/UI смен и привязать проведение к открытой смене.
4. Добавить конкурентные тесты открытия/закрытия и проведения.

## P1

1. Провести live TLS/reverse-proxy smoke в выделенном тестовом deployment.
2. Выполнить Browser E2E авторизации, dashboard, операций, отчётов, ролей, тем и reduced-motion.
3. Выполнить backup/restore на отдельной тестовой БД и проверить запуск API после восстановления.
4. Добавить филиал как сущность только если это утверждено предметной областью; не подменять филиал кассой.

## P2

1. Опционально связать кассовый документ с заказом/договором.
2. Расширить отчётность по филиалам, контрагентам и каналам продаж.
3. Добавить нагрузочные измерения и EXPLAIN ANALYZE.

## Критерии приёмки

Каждый пункт должен иметь автоматический тест, журнал результата и ссылку на конкретный commit/файл. Статус READY запрещён при BLOCKED по P0/P1.
