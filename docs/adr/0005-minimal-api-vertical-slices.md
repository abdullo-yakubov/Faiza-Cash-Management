# ADR-0005. Minimal API и группировка по функциям вместо контроллеров

**Статус:** принято; группировка по функциям реализована частично.

## Контекст

ASP.NET Core предлагает два способа описания HTTP-интерфейса: MVC-контроллеры (классы с атрибутами) и Minimal API (`app.MapPost(...)` с лямбдами). Для кассовой системы важны: явный список маршрутов с ролями, минимум «магии» (фильтров, привязки моделей по соглашениям), быстрый старт и простота интеграционного тестирования.

## Решение

- Использовать **Minimal API**: каждый маршрут регистрируется явно вместе с требованиями авторизации, ограничением частоты и метаданными доступа (`x-faiza-access` в OpenAPI).
- Группировать обработчики **по функциональным срезам** (vertical slices): справочники, аудит, отчёты, операции и т. д. — отдельные статические классы-регистраторы. Внутри среза обработчик сам выполняет валидацию, проверку доступа, работу с EF Core и аудит; общие бизнес-правила вынесены в слой Application.
- Новые функции волны 1 (согласование, вложения, авансы, инвентаризация, панель администратора) оформляются отдельными срезами, а не добавляются в общий файл.

## Последствия

- (+) Маршрут, роль и логика видны в одном месте; тест «роль × маршрут» строится автоматически по OpenAPI.
- (+) Меньше накладных расходов на запуск и проще контейнер.
- (−) Без дисциплины срезы разрастаются: в базовой версии основной файл обработчиков превысил 80 КБ. Рекомендация — разнести его по срезам (операции, смены, переводы, расчёты) при ближайшем рефакторинге; это не меняет внешний контракт.
- (−) Нет встроенных фильтров MVC — сквозная логика реализована middleware (Request → Auth → RateLimit → Access → DirectoryCache).

## Альтернативы

1. **MVC-контроллеры** — привычнее, но больше шаблонного кода; правила доступа рассеяны по атрибутам и фильтрам.
2. **CQRS с MediatR** — даёт чистые срезы, но добавляет зависимость и уровень косвенности, избыточный для одного разработчика и ~80 маршрутов.
3. **Carter / FastEndpoints** — сторонние надстройки над Minimal API; не дают существенных преимуществ для объёма проекта.
