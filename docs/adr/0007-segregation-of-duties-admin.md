# ADR-0007. Разделение обязанностей: администратор без финансовых операций

**Статус:** принято, реализуется в волне 1. Заменяет «известное ограничение № 1» ТЗ ред. 5.0.

## Контекст

В базовой версии роль `admin` могла и настраивать систему (пользователи, доступы, кассы), и выполнять финансовые операции. Это нарушает принцип разделения обязанностей: один человек может выдать себе доступ к кассе, провести расход и при необходимости управлять резервными копиями. В кассовом учёте лицо, контролирующее систему, не должно распоряжаться деньгами. Аналогично автор крупного расхода не должен сам его утверждать.

## Решение

1. Роль `admin` теряет право на финансовые операции: создание, изменение, удаление и проведение черновиков, сторно, открытие и закрытие смен, переводы, приём квитанций, распределение платежей, авансы, инвентаризацию. Сервер отвечает 403.
2. Admin сохраняет настройку системы, пользователей, касс, доступов, резервные копии, курсы валют, номиналы, логотип, панель состояния и **чтение** всех данных.
3. Вводится согласование расходов: при сумме не меньше порога проведение требует решения руководителя (`manager`), который не является автором документа (иначе 409).
4. Кассир по-прежнему проводит только собственные черновики.
5. Матрица прав (приложение А ТЗ по ГОСТ) — единственный источник истины; её соблюдение проверяется тестом «роль × маршрут» по всем маршрутам.

## Последствия

- (+) Для хищения требуется сговор минимум двух лиц (автор + согласующий, или admin + финансовая роль).
- (+) Аргумент для комиссии и заказчика: система реализует внутренний контроль, а не только учёт.
- (−) Малому штату нужен минимум два человека: администратор и бухгалтер. Совмещение `admin` с финансовой ролью технически возможно назначением нескольких ролей — допустимость решает заказчик `[УТОЧНИТЬ У ЗАКАЗЧИКА]`; рекомендуется запретить.
- (−) Демонстрационные сценарии и тесты, где admin проводил документы, нужно переписать на `accountant`/`cashier`.
- (−) Создание задолженностей и квитанций, ввод начального остатка остаются у admin, т. к. не входят в утверждённый перечень — вопрос вынесен заказчику.

## Альтернативы

1. **Оставить как было и описать как ограничение** — не соответствует целям автоматизации контроля. Отклонено.
2. **Отдельная роль «суперпользователь» с финансовыми правами** — сохраняет проблему.
3. **Двойная подпись на любую операцию** — избыточно замедляет кассу; порог согласования даёт баланс между контролем и скоростью.
