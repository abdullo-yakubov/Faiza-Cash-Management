# ADR-0004. Деньги — decimal, в JSON — строка

**Статус:** принято, реализовано.

## Контекст

Двоичные числа с плавающей точкой не представляют точно десятичные дроби: в JavaScript `0.1 + 0.2 = 0.30000000000000004`. Число JSON в браузере всегда становится `double`, и суммы больше 2⁵³ (≈ 9·10¹⁵) теряют точность. Система допускает суммы до 9 999 999 999 999 999,99 — это больше, чем точно представимо в `double`.

## Решение

- В БД — `numeric` с 2 знаками; в C# — `decimal`; проверка допустимости — единая функция `Money.IsValid` (больше 0, ровно 2 знака, не больше максимума).
- В JSON суммы передаются **строкой** (`"1500.00"`) через собственный конвертер; при чтении принимаются строка и число, при записи — всегда строка с двумя знаками.
- Во frontend итоги не считаются в `number`: ввод с «,» или «.» нормализуется в строку, а суммирование выполняется целыми копейками (`BigInt`) либо берётся с сервера.
- Расчёты остатка, разницы смены, пересчёта по купюрам, остатка аванса выполняются только на сервере.

## Последствия

- (+) Нет ошибок округления; итоги отчётов, панели и SQL-оракула совпадают до копейки (тест инвариантов).
- (+) Поддерживается полный диапазон сумм.
- (−) Клиентский код не может просто сложить поля ответа — нужен помощник форматирования/сложения.
- (−) Сторонние клиенты API должны знать о строковом формате (отражено в OpenAPI).

## Альтернативы

1. **Целые копейки (`long`) в API** — точно, но неудобно читать и легко ошибиться в масштабе для валют с другим числом знаков.
2. **Число JSON** — теряет точность. Отклонено.
3. **Библиотека decimal.js на клиенте** — лишняя зависимость при том, что итоги считает сервер.
